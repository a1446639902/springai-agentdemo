本版两件事，都是 v1.20.0 发布次日（2026-09-06）生产环境实测暴露的事故修复：**① 工具超时不再杀掉整回合**——Brave 搜索 20 秒超时曾把整回合连同已完成的对话进度一起报废；现在超时错误作为工具结果回给模型，模型自行换路（如改用博查搜索），回合继续。**② 网关 503 等瞬态 5xx 真正进入自动重试**——智谱网关一次 503 曾让回合直接失败且 API 恢复后也救不回；现在 SDK 系 5xx/429 与 WebClient 系同判据重试（L1 传输层 + L2 回合续跑自动生效）。

## 修复一：工具超时/中断不再杀掉整回合

**事故形态**（v1.20.0 生产日志，回合 10）：`BraveWebSearch 超时（超过 20 秒未返回）`——工具层超时包装器抛出的 `IllegalStateException` 一路穿透两道工具容错防线，`CodingAgent` 把整回合标成失败：已完成的对话进度全部报废，屏幕出现「⚠ 出错」。讽刺的是，工具「真的挂了」（如网络不可达）反而能被兜住——因为 `MethodToolCallback` 把这类异常包装成 `ToolExecutionException`，会被转成错误文本回给模型；而超时保护这个「善意的包装」用的异常类型不对，恰好绕过了兜底。

**根因**：Spring AI 的 `DefaultToolCallingManager` 只把 `ToolExecutionException` 交给异常处理器转文本回模型；`TimeLimitedToolCallback`（Brave 的 20 秒总超时包装器）的超时/中断分支抛的是 `IllegalStateException`，异常处理器不认，直接冒泡终止回合。同理，`ResilientToolCallingManager`（工具名拼错的容错层）只接「No ToolCallback found」一种 `IllegalStateException`，也拦不住它。

**修复**：超时、中断、不可传播的受检异常三个分支统一包装为 `ToolExecutionException`（携带真实工具定义）。修复后行为：

- 工具超时 → 错误文本（「工具 BraveWebSearch 执行出错：…超时…」）回给模型 → 模型自行调整（换博查搜索 / 换参数重试 / 向用户说明），**回合继续**；
- 回给模型的错误文案不变（可读文案放内层 cause，处理器取 cause 链首个非空 message）；
- 委托工具自己的 `RuntimeException` 仍原样传播（既定语义，多数本身就是 `ToolExecutionException`，本就能被兜住）；
- 中断分支（Esc 取消回合时工具被 cancel）同修——不再以会穿透防线的异常类型出现。

## 修复二：网关 503 等 SDK 系瞬态 5xx 进入自动重试

**事故形态**（同日生产日志）：智谱网关返回 503 `Service temporarily unavailable`，60 次直接杀回合；且该回合就此失败，API 恢复后也不会自愈。用户侧观感：「只要报过 503，之后一直报错」。

**根因**：v1.20.0 的两层重试（L1 传输层零下发重试 + L2 回合续跑）判据在 `RetryPolicy` 唯一真相源，其中「网关 5xx 重试」只认 `WebClientResponseException`——但智谱/Qwen/OpenAI/opencode-go 这些走 openai-java SDK（OkHttp 栈）的 provider，503 抛的是 SDK 自己的 `InternalServerException`：不是 IOException、不是 WebClientResponseException、message 无关键词，四条瞬态判据全部落空。同一个「网关 5xx」语义，WebClient 系重试、SDK 系判死刑——不对称缺口。

**修复**：`RetryPolicy.shouldRetry` 的 cause 链循环新增 `OpenAIServiceException` 分支（SDK 系 HTTP 状态异常的公共父类，源码核对：SDK 把 500..599 全区间映射为 `InternalServerException`），与 WebClient 分支完全镜像：

- `statusCode >= 500 || statusCode == 429` → 瞬态，可重试；
- 其余 4xx（400/401/403/404/422）→ 红线否决（欠费、密钥错、请求有病——重试只会更慢更花钱），与 WebClient 4xx 同口径。

判据是唯一真相源，两处自动生效，无需配置：主 agent L1（零下发 503 重试 4 次，叠加 SDK 内部自带 2 次）+ L2（mid-stream 503 走回合续跑，API 恢复后自愈）+ 子 agent 同步路径（5 次尝试）。取消/中断红线不动（Esc 取消优先级最高）；SDK 内部的 `OpenAIRetryableException` 不越权接管（SDK 已自带 2 次重试）。

## 测试

两个修复均按 TDD（先红后绿）：

- `TimeLimitedToolCallbackTest`：新增超时/中断两个回归测试（断言异常类型为 `ToolExecutionException`、携带工具定义、保留可读文案），先验证失败（实际抛 `IllegalStateException`）再实现转绿。
- `RetryPolicyTest`：新增真 SDK 异常类型用例（非 Fake 类）——`InternalServerException` 503 生产形态（按真实传播形态 `CompletionException` 包装）/ 5xx 区间边界 500 与 599 / `RateLimitException` 429 重试 / `UnauthorizedException` 401、`BadRequestException` 400、`UnexpectedStatusCodeException` 418 红线否决 / 取消红线优先于 503 短路；全部进既有等价性比对集合（钉住委托不漂移）。
